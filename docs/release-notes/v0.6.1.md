Arreglos de Linux y de la barra lateral: el selector de archivos y carpetas ya no bloquea la ventana y, si el sistema no puede abrirlo, Código lo dice y deja escribir la ruta; el terminal elige su shell con más cuidado y explica por qué no arranca.

*Linux and sidebar fixes: the file and folder chooser no longer blocks the window and, when the system cannot open it, Código says so and lets you type the path; the terminal picks its shell more carefully and says why it did not start.*

## Español

### Correcciones

- **Selector de archivos y carpetas.** *Abrir carpeta…*, *Abrir archivo…*, *Guardar como…*, la
  carpeta de *Clonar repositorio…* y la de *Nueva app Nodalia* piden el selector del sistema
  (el portal XDG, es decir, tu aplicación de archivos predeterminada) desde un hilo aparte y
  asociado a la ventana de Código, en lugar de bloquear la ventana mientras se abre. Antes, si no
  había portal ni `zenity`, o el diálogo no llegaba a abrirse, no pasaba nada y no se decía nada.
  Ahora Código lo detecta, avisa, y abre una ventana donde puedes escribir la ruta, con
  comprobaciones (que sea una carpeta, que sea un archivo, que exista la carpeta donde guardar).
- **Terminal.** El shell se elige entre `$SHELL`, el que figura en `/etc/passwd` y los
  habituales (`bash`, `zsh`, `sh`), saltando los que no existan o no se puedan ejecutar; antes
  solo se miraba `$SHELL`, y un valor obsoleto lo dejaba sin shell. El terminal declara `SHELL` y
  una codificación UTF-8 si el entorno no trae ninguna, y si la carpeta del proyecto ya no
  existe arranca en tu carpeta personal. Si no arranca, el aviso dice el motivo.
- **Barra lateral.** Ya no va pegada al borde de su isla: la fila de iconos y todos los paneles
  (Archivos, Buscar, Calidad, Asistente…) tienen el mismo margen interior que las demás apps
  de Ingeniería.

### Notas

- **Probado en la aplicación real** (Linux, X11, sin portal ni `zenity` instalados): el selector
  no puede abrirse, Código avisa, la ventana de ruta abre la carpeta escrita, y el terminal
  muestra el shell real en un pseudo-terminal (`/dev/pts/0`); la barra lateral, vista en los paneles Archivos y Asistente. Las pruebas automáticas cubren la
  elección del shell, la carpeta desaparecida y las reglas de la ruta escrita.
- **No probado**: el selector nativo del portal en un escritorio real (GNOME, KDE…); en este
  entorno no hay ninguno. Si en tu equipo sigue sin abrirse, Código ahora lo dice en un aviso y
  ofrece escribir la ruta. No pude reproducir el fallo del terminal; los cambios endurecen la
  elección del shell y el aviso de error. Si te sigue ocurriendo, el aviso indica la causa.

## English

### Fixes

- **File and folder chooser.** *Open folder…*, *Open file…*, *Save as…*, the folder of *Clone
  repository…* and the one of *New Nodalia app* ask for the system chooser (the XDG portal, that
  is, your default files application) from a separate thread and tied to Código's window,
  instead of blocking the window while it opens. Before, when there was no portal or `zenity`,
  or the dialog never opened, nothing happened and nothing was said. Now Código detects it,
  says so, and opens a window where you can type the path, with checks (it is a folder, it is a
  file, the folder to save in exists).
- **Terminal.** The shell is chosen among `$SHELL`, the one listed in `/etc/passwd` and the usual
  ones (`bash`, `zsh`, `sh`), skipping those that do not exist or cannot be run; before, only
  `$SHELL` was looked at, and a stale value left it without a shell. The terminal sets `SHELL`
  and a UTF-8 locale when the environment has none, and if the project folder is gone it starts in
  your home folder. When it does not start, the notice gives the reason.
- **Sidebar.** It no longer sits against the edge of its island: the icon row and every panel
  (Files, Search, Quality, Assistant…) have the same inner margin as the other Engineering apps.

### Notes

- **Tried in the real app** (Linux, X11, with no portal or `zenity` installed): the chooser
  cannot open, Código says so, the path window opens the folder typed, and the terminal shows
  the real shell in a pseudo-terminal (`/dev/pts/0`); the sidebar, looked at in the Files and Assistant panels. The automatic tests cover the shell choice,
  the vanished folder and the rules for a typed path.
- **Not tried**: the portal's native chooser on a real desktop (GNOME, KDE…); there is none in
  this environment. If it still does not open on your machine, Código now says so in a notice and
  offers to type the path. I could not reproduce the terminal failure; the changes harden the
  shell choice and the error notice. If it still happens, the notice names the cause.
