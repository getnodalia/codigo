Novedades: el asistente de Código ahora ve tu código (el archivo abierto, la selección y el proyecto) y escribe cambios que aceptas o rechazas con una vista de diferencias, y las descripciones y comentarios de GitHub y GitLab se dibujan como Markdown.

*What's new: Código's assistant now sees your code (the open file, the selection and the project) and writes changes that you accept or reject from a diff, and GitHub and GitLab descriptions and comments are drawn as Markdown.*

## Español

### Novedades

- **El asistente ve tu código.** Cada pregunta lleva, además de lo que escribes, el archivo abierto
  (una ventana de hasta 40 000 caracteres alrededor del cursor), la selección, las pestañas abiertas
  y la lista de archivos del proyecto. Con `@nombre` adjuntas otro archivo. Debajo del cuadro de
  texto el panel dice qué ve. Un interruptor en Preferencias ▸ Asistente lo desactiva.
- **El asistente escribe código.** Cuando la respuesta cambia algo, el panel muestra una tarjeta por
  archivo con las líneas quitadas y añadidas: *Cambiar src/main.rs* o *Archivo nuevo src/util.rs*,
  con *Aplicar*, *Rechazar* y *Aplicar los N cambios*. Un cambio en un archivo abierto pasa por el
  editor, así que *Deshacer* devuelve el código anterior; un archivo nuevo se crea y se abre.
  Si las líneas que el modelo dice cambiar no están en el archivo (o están dos veces), la tarjeta lo
  dice y no toca nada.
- **Markdown de verdad en las solicitudes.** Las descripciones y comentarios de las solicitudes de
  incorporación, las solicitudes de fusión y las incidencias se mostraban como texto plano, con los
  `##`, los comentarios HTML y las etiquetas a la vista. Ahora se dibujan con el estilo de Nodalia:
  títulos, negrita, cursiva, tachado, código en línea y en bloque, listas con casillas de tareas,
  citas, tablas, reglas y enlaces. El HTML nunca se ejecuta: los comentarios desaparecen, se
  entienden `<br>`, `<a>`, `<img>`, `<b>`, `<i>` y `<code>` y el resto de etiquetas se quita
  dejando su texto. Las imágenes no se descargan: aparecen como un enlace con su texto alternativo.
  Solo se abren enlaces `http`, `https` y `mailto`.

### Notas

- **Probado en la aplicación real** (Linux, X11) contra un servidor local compatible con OpenAI que
  responde con bloques de edición: el panel muestra lo que ve, las tarjetas de diferencias, *Aplicar
  los 2 cambios* modifica el archivo abierto y crea el nuevo, y *Deshacer* restaura el código. El Markdown se dibujó en la aplicación real con una descripción de ejemplo (títulos, listas, casillas, código, cita, tabla, comentarios HTML y un pie con enlaces e imagen); pruebas automáticas cubren su lectura, el texto hostil y el dibujo. No probado con una cuenta real de GitHub o GitLab. Las
  pruebas automáticas cubren la lectura de los bloques, las ventanas de contexto y las menciones.
- **No probado**: los servicios reales de Anthropic y OpenAI y el llavero (cómo de bien siguen el
  formato de bloques dependerá del modelo), macOS y Windows.
- **Todavía no**: un agente que ejecute herramientas o comandos, completado en línea mientras
  escribes y revisión de un cambio por calidad y seguridad.

## English

### What's new

- **The assistant sees your code.** Every question carries, besides what you type, the open file (a
  window of up to 40,000 characters around the caret), the selection, the open tabs and the
  project's file list. `@name` attaches another file. Under the text box the panel says what it
  sees. A switch in Preferences ▸ Assistant turns it off.
- **The assistant writes code.** When the answer changes something, the panel shows one card per
  file with the lines removed and added: *Change src/main.rs* or *New file src/util.rs*, with
  *Apply*, *Reject* and *Apply all N changes*. A change to an open file goes through the editor, so
  *Undo* brings the old code back; a new file is created and opened. If the lines the model says
  to change are not in the file (or are there twice), the card says so and touches nothing.
- **Real Markdown in pull requests.** The descriptions and comments of pull requests, merge
  requests and issues were shown as plain text, with the `##`, the HTML comments and the tags in
  view. They are now drawn in the Nodalia style: headings, bold, italic, strikethrough, inline and
  block code, lists with task boxes, quotes, tables, rules and links. HTML is never run: comments
  vanish, `<br>`, `<a>`, `<img>`, `<b>`, `<i>` and `<code>` are understood and every other tag is
  removed with its text kept. Images are not downloaded: they appear as a link with their alt text.
  Only `http`, `https` and `mailto` links open.

### Notes

- **Tried in the real app** (Linux, X11) against a local OpenAI-compatible server that replies with
  edit blocks: the panel shows what it sees, the diff cards, *Apply all 2 changes* changes the open
  file and creates the new one, and *Undo* restores the code. The Markdown was drawn in the real app from a sample description (headings, lists, task boxes, code, quote, table, HTML comments and a footer of links and a picture); automatic tests cover reading it, hostile text and drawing. Not tried against a live GitHub or GitLab account. Automatic tests cover reading the
  blocks, the context windows and the mentions.
- **Not tried**: the real Anthropic and OpenAI services and the keyring (how well they follow the
  block format will depend on the model), macOS and Windows.
- **Not yet**: an agent that runs tools or commands, inline completion as you type and a review of
  a change for quality and security.
