Novedades: GitLab llega a Código con el mismo trato que GitHub, con los iconos reales de las dos aplicaciones en la barra lateral, y las Preferencias ganan una página de Cuentas.

*What's new: GitLab comes to Código with the same treatment as GitHub, with the two services' own marks in the sidebar, and Preferences gains an Accounts page.*

## Español

### Novedades

- **GitLab, nativo.** Un panel (`Ctrl+Alt+L`) con las solicitudes de fusión e incidencias abiertas
  del proyecto en el que estás, las que abriste o esperan tu revisión y tus proyectos. Una
  solicitud de fusión se abre en su ventana con la descripción, el estado del pipeline, los archivos
  cambiados con sus diferencias y la conversación; puedes comentar, aprobar o abrirla en GitLab.
  *Crear una solicitud de fusión…* sube la rama actual y la abre. *Clonar un proyecto de GitLab…*
  acepta una dirección o `grupo/proyecto`.
- **gitlab.com o tu propio servidor.** El servidor se elige en Preferencias ▸ Cuentas. Se inicia
  sesión con un token de acceso personal (ámbito `api`; el panel enlaza a la página que lo crea).
  El token vive en el llavero del sistema, una entrada por servidor, solo se envía a ese servidor
  por HTTPS y nunca se escribe en un archivo ni aparece en un error.
- **Git con GitLab.** Subir, bajar y clonar un proyecto del servidor en el que has iniciado sesión
  usan ese mismo token.
- **Los iconos reales.** GitHub y GitLab llevan su propia marca en la barra lateral, tintada con
  el color de la interfaz.
- **Preferencias ▸ Cuentas.** Quién tiene la sesión iniciada en GitHub y en GitLab y el servidor
  de GitLab.

### Notas

- **Probado en la aplicación real** (Linux, X11): el panel y su pestaña con la marca, el inicio de
  sesión con un token incorrecto contra gitlab.com real (lo dice con claridad), la página Cuentas.
  Pruebas automáticas cubren la lectura de las respuestas de GitLab, las direcciones y remotos, la
  validación del servidor y que el token nunca aparezca en un error.
- **No probado contra una cuenta real**: las listas, comentar, aprobar, crear una solicitud de
  fusión, el llavero y clonar un proyecto privado. macOS y Windows reales tampoco.
- **Todavía no**: iniciar sesión por el navegador (OAuth) en GitLab, ver y responder comentarios en
  una línea de las diferencias, e importar un tema de VS Code.

## English

### What's new

- **Native GitLab.** A panel (`Ctrl+Alt+L`) with the open merge requests and issues of the project
  you are in, the ones you opened or that wait for your review, and your projects. A merge request
  opens in its own window with its description, pipeline status, changed files with their diffs and
  the conversation; you can comment, approve or open it on GitLab. *Create a merge request…* pushes
  the current branch and opens one. *Clone a GitLab project…* takes an address or `group/project`.
- **gitlab.com or your own server.** The server is chosen in Preferences ▸ Accounts. You sign in
  with a personal access token (the `api` scope; the panel links to the page that creates it). The
  token lives in the system's keyring, one entry per server, is sent only to that server over HTTPS
  and is never written to a file or shown in an error.
- **Git with GitLab.** Pushing, pulling and cloning a project on the server you are signed in to use
  that same token.
- **The real marks.** GitHub and GitLab carry their own mark in the sidebar, tinted with the
  interface colour.
- **Preferences ▸ Accounts.** Who is signed in to GitHub and GitLab, and the GitLab server.

### Notes

- **Tried in the real app** (Linux, X11): the panel and its tab with the mark, signing in with a
  wrong token against the real gitlab.com (it says so plainly), the Accounts page. Automatic tests
  cover reading GitLab's answers, addresses and remotes, validating the server and the token never
  appearing in an error.
- **Not tried against a real account**: the lists, commenting, approving, creating a merge request,
  the keyring and cloning a private project. Real macOS and Windows neither.
- **Not yet**: browser (OAuth) sign-in for GitLab, seeing and answering comments on a line of the
  diff, and importing a VS Code theme.
